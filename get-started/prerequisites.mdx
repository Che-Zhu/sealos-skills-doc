使用 Sealos Skills 部署前，确认以下账号与工具。

## Sealos Cloud 账号

部署需要 Sealos Cloud 账号。`local` 环境下 Phase 0 完成区域选择、登录与工作空间选择。

## 工具

Phase 0 按运行环境探测依赖。缺失时一次列出并询问用户，同意后安装。完整规则见 [Phase 0 — 部署前环境检查](/pipeline/phases/phase-0-preflight)。

**`local` 与 `sandbox` 共用：** Git、Node.js 18+、Python 3.8+ 与 PyYAML、kompose、Helm 3+、kubectl、curl、jq

**仅 `local`（Phase 3 构建路径）：** `gh`（二进制必装；登录与 `write:packages` 在选定 GHCR 推送时再强制）、Docker CLI、运行中的 Docker daemon、Docker Buildx、railpack（`sandbox` 已预装 railpack，Phase 3 使用 **k8s-kaniko-job** skill，无需 Buildx）

**按需（仓库声明时）：** Git LFS、子模块拉取

**不列入必装二进制（`npx`）：** `sealos-cli`；`@norberia/agentlens`（Phase 2 部署侦察）

## GitHub CLI 与 GHCR 访问

`local` 与 `sandbox` 均由主 Agent 在 Phase 3 将新构建镜像推送到 GHCR。`local` 须在**实际推送前**完成 `gh` 登录且具备 `write:packages`；Phase 0 仅警告，不因此 STOP。`sandbox` 使用环境注入的 `GITHUB_TOKEN` 等凭证。复用已有 digest 的路径不需要 GHCR 推送权限。

## 验证命令

```bash
docker info
gh auth status
kubectl --kubeconfig ~/.sealos/kubeconfig get ns
```
