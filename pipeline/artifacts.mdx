流水线输出均写入目标项目目录下的 `.sealos/`。

```
{WORK_DIR}/.sealos/
├── config.json
├── state.json
├── analysis.json
├── phase-2/
│   ├── gitingest-digest.txt
│   ├── deployment-plan.json
│   └── docker-compose.yml
├── phase-3/
│   └── build-result.json
├── phase-4/
│   ├── image-digests.json
│   ├── source/
│   ├── rendered.yaml
│   └── resource-map.json
└── template/
    └── index.yaml
```

## 主要产物说明

| 文件 | 写入阶段 | 读取阶段 | 说明 |
| --- | --- | --- | --- |
| `analysis.json` | Phase 0–2 | Phase 3–4 | Phase 2 新增 `deployment_plan`；Phase 3 新增 `build_result`（仅在本 Phase 运行后） |
| `phase-2/deployment-plan.json` | Phase 2 | Phase 3、4 | 含 `deployment_source` 指针 |
| `phase-2/gitingest-digest.txt` | Phase 2 | Phase 2 | gitingest 侦察输入 |
| `phase-2/docker-compose.yml` | Phase 2 | Phase 3、4 | Canonical compose（非 Helm/K8s 时） |
| `template/index.yaml` | Phase 4 或后续官方模板路径 | Phase 4.5、5 | Canonical 部署模板 |
| `phase-3/build-result.json` | Phase 3 | Phase 4 | 已推送镜像的 tag 引用（`pushed`）与 `pull_access` |
| `phase-4/image-digests.json` | Phase 4 | Phase 4 | 全部容器镜像的 `repository@sha256:...`（`linux/amd64`） |
| `phase-4/` | Phase 4 | — | 转换中间产物（`source/`、`rendered.yaml`、`resource-map.json`） |
| `state.json` | Phase 5.5 后 | 部署模式识别、UPDATE | 部署状态与服务映射 |
| `config.json` | 用户或 4.5 | Phase 4.5 | 用户配置覆盖 |

字段契约见 [deployment-plan.json](/specs/deployment-plan)。其他 JSON 产物见 [产物 Schema](/specs/artifact-schemas)。
