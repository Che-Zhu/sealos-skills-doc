流水线输出均写入目标项目目录下的 `.sealos/`。

```
{WORK_DIR}/.sealos/
├── config.json
├── state.json
├── analysis.json
├── phase-2/
│   ├── gitingest-digest.txt
│   └── deployment-plan.json
├── deployment-source/
│   ├── rendered.yaml
│   └── resource-map.json
├── topology-evidence/
│   └── {app-name}.yaml
├── build/
│   └── {service-key}/
│       └── build-result.json
└── template/
    └── index.yaml
```

## 主要产物说明

| 文件 | 写入阶段 | 读取阶段 | 说明 |
| --- | --- | --- | --- |
| `analysis.json` | Phase 0、Phase 1–2 | Phase 3–4 | 含 `deployment_plan` 路径及清单字段 |
| `phase-2/deployment-plan.json` | Phase 2 | Phase 2、3、4 | Subagent 产出的可部署组件清单 |
| `phase-2/gitingest-digest.txt` | Phase 2 | Phase 2 | gitingest 侦察输入 |
| `template/index.yaml` | Phase 4 或后续官方模板路径 | Phase 4.5、5 | Canonical 部署模板 |
| `build/*/build-result.json` | Phase 3 | Phase 4 | 构建 digest 与拉取元数据 |
| `state.json` | Phase 5.5 后 | 部署模式识别、UPDATE | 部署状态与服务映射 |
| `config.json` | 用户或 4.5 | Phase 4.5 | 用户配置覆盖 |

字段契约见 [deployment-plan.json](/specs/deployment-plan)。其他 JSON 产物见 [产物 Schema](/specs/artifact-schemas)。
