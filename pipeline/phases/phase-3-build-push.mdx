## 目的

Phase 3 由主 Agent 编排：**Subagent 按顺序构建**须构建的镜像，全部成功后由**主 Agent 统一推送**到用户 GHCR，并写入 `.sealos/phase-3/build-result.json`（**推送引用**与 `pull_access`，不含模板用 digest 表）。构建后端取决于 `analysis.json` 中的 `runtime_profile`；**推送始终由主 Agent 完成**。

所有镜像 tag → digest 的固定由 [Phase 4](/pipeline/phases/phase-4-template) 统一完成。

本阶段不做仓库侦察、不运行 railpack、不生成 Dockerfile、不修改 `deployment_source`（配方错误返回 Phase 2）。

## 前置条件

- Phase 4 判定须构建且尚未完成推送时调用（不由 Phase 2 直接调用）

## 输入

| 输入 | 来源 |
| --- | --- |
| `runtime_profile` | `analysis.json`（Phase 0） |
| 部署计划 | `analysis.json` → `deployment_plan` → `deployment-plan.json` |
| 部署源 | `deployment-plan.json` → `deployment_source` |
| 构建目标 | 从部署源解析（见下表） |
| GitHub 认证 | Phase 0；推送由主 Agent 完成（`local` 用 `gh`；`sandbox` 用注入的 `GITHUB_TOKEN` 等） |

### 构建方式（按 `runtime_profile`）

| `runtime_profile` | 构建方式 | 说明 |
| --- | --- | --- |
| `local` | Docker Buildx | Subagent 本地**仅构建**；主 Agent 统一推送 GHCR |
| `sandbox` | [`k8s-kaniko-job`](/skills/k8s-kaniko-job) skill | sandbox 无 Buildx；Subagent 通过 Kaniko Job 在集群内**仅构建** |

两种环境均构建 `linux/amd64`。`sandbox` 不调用 Buildx，不要求本地 Docker daemon。

### 推断部署源类型

按 `deployment_source` 路径推断（与 [Phase 4](/pipeline/phases/phase-4-template) 一致）：

| 路径特征 | 类型 |
| --- | --- |
| `.sealos/phase-2/docker-compose.yml` | Compose |
| 含 `Chart.yaml` 的目录 | Helm |
| 单个 `.yaml` / `.yml` 文件 | Kubernetes |

### 从部署源解析构建目标

| 类型 | 解析方式 |
| --- | --- |
| Compose | 每个含 `build:` 的服务；以 `build.context` 为上下文、`build.dockerfile` 为 Dockerfile（相对 `work_dir`） |
| Helm | `helm template` 渲染后，镜像须本地构建且 Phase 2 已准备 Dockerfile 的工作负载 |
| Kubernetes | 清单中镜像须本地构建且 Phase 2 已准备 Dockerfile 的容器 |

仅含上游 `image:`（如 `postgres:16-alpine`）且无 `build` 的组件不在本阶段构建。路径均相对 `analysis.json` 中的 `work_dir`。

## 输出

| 输出 | 路径 | 说明 |
| --- | --- | --- |
| 构建结果 | `.sealos/phase-3/build-result.json` | 已推送镜像的 tag 引用与 `pull_access` |
| `analysis.json` | `.sealos/analysis.json` | 新增 `build_result` 指针 |

## 流程

### 1. 主 Agent — 解析构建队列

读取 `runtime_profile`。从 `deployment_source` 列出须构建的目标（服务 key、context、dockerfile）。无目标则跳过本 Phase。

### 2. Subagent — 按顺序构建

对每个目标**依次**启动一个 Subagent：

- **并发上限 1**：同时最多运行一个 Subagent，禁止并行构建。
- Subagent 输入：当前目标、部署源路径、`work_dir`、`runtime_profile`、context 与 dockerfile 路径。
- **`local`**：Subagent 仅用 Buildx 执行本地构建，**不**推送到 registry。
- **`sandbox`**：Subagent 调用 **k8s-kaniko-job** skill，在集群内以 Kaniko Job **仅构建**，**不**推送到 registry。
- 构建配方无效（Dockerfile 缺失、上下文无效、语法错误）→ **RETURN → Phase 2** 步骤 3。
- 单次构建失败经补救仍失败 → **STOP**。

### 3. 主 Agent — 统一推送 GHCR

全部 Subagent 构建成功后，**主 Agent**（`local` 与 `sandbox` 相同）：

- 将本阶段新构建的镜像**统一**推送到当前 GitHub 用户的 GHCR（用户不选择 registry）。
- 每次推送使用**唯一版本标识**打标签；将可拉取的 tag 引用记入 `pushed`（见步骤 4）。
- `local`：从本地 Buildx 构建产物推送；检查 `gh` 登录与 `write:packages`。
- `sandbox`：从 Kaniko Job 构建产物推送；使用环境注入的 `GITHUB_TOKEN` 等凭证（不依赖本地 `gh`）。
- 推送后对每个镜像做匿名拉取探测：成功记 `pull_access: public`，否则记 `ghcr_secret_required`。
- 推送到 `ghcr.io/{user}/...` 失败属 Phase 3 执行失败。

应用中所有私有或不确定的 GHCR 镜像须共享一个规范化 GHCR namespace。混合 namespace 在创建云端资源前停止。

### 4. 主 Agent — 写入 `build-result.json`

将结果写入 `.sealos/phase-3/build-result.json`。`pushed` 中每项为推送后的 tag 引用（`repository:tag` 或带 registry 的完整引用），key 与部署源工作负载名对齐。**不得**在此文件写入模板最终用的 `repository@sha256:...` digest 表。

示例：

```json
{
  "generated_at": "2026-08-02T14:00:00Z",
  "pushed": {
    "web": "ghcr.io/user/myapp-web:20260802-web-abc123",
    "worker": "ghcr.io/user/myapp-worker:20260802-worker-def456"
  },
  "pull_access": {
    "web": "public",
    "worker": "ghcr_secret_required"
  }
}
```

`pull_access` 供 Phase 4 模板生成时决定是否附加 pull-secret。

### 5. 主 Agent — 写入 `analysis.json`

与既有字段合并，仅新增 `build_result` 指针：

```json
{
  "build_result": ".sealos/phase-3/build-result.json"
}
```

不得修改 Phase 0–2 已写字段。`build-result.json` 须通过 schema 后，合并后的 `analysis.json` 须通过 [产物 Schema](/specs/artifact-schemas) 再落盘。

本 Phase 被跳过时（无需构建）不写入 `build_result`。

## 停止条件

| 结果 | 条件 |
| --- | --- |
| **CONTINUE → Phase 4** | 全部构建与推送成功，或无需构建 |
| **RETURN → Phase 2** | 某服务构建配方失败 |
| **STOP** | 补救后构建或推送失败，或 namespace 冲突 |

## 验收标准

- `.sealos/phase-3/build-result.json` 存在且通过 schema
- `analysis.json` 含 `build_result` 且路径正确
- `pushed` 覆盖本阶段所有已推送服务
- 未重建的上游镜像未出现在 `pushed`
