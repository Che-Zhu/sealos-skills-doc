## 目的

Phase 7 从线上云状态判断部署是否真正成功，并完成状态记录。不仅凭模板输出或 API 返回码。

Phase 7 对每次部署为必需。创建资源而无部署后收尾不算部署成功。

## 阶段约束

进入本 Phase 时须知晓，并在**执行过程中**遵守。

| ID | 约束 | 说明 |
| --- | --- | --- |
| P7-01 | 不得仅凭 API 返回码判断成功 | 须核对线上运行状态 |
| P7-02 | 架构不匹配时不得猜测镜像或浮动标签 | 见失败处理 |
| P7-03 | 向用户报告成功前须写完 `state.json` | 见 [状态与完成](/pipeline/state-and-completion) |

## 阶段验收

Phase 7 **产出落盘后**运行：

```bash
node skills/sealos-deploy/scripts/validate-phase-7.mjs --dir "$WORK_DIR"
```

脚本核对：

| ID | 核对项 |
| --- | --- |
| P7-V01 | `.sealos/state.json` 存在且通过 schema |
| P7-V02 | `state.json` 中 `app_name` 与 Phase 6 `deploy-result.json` 一致 |

未通过 → 不得向用户报告 **COMPLETE**。

## 流程

### 1. 运行验收

Agent 须按工作负载类型验证适用项：

- [ ] App、工作空间、资源范围与访问 URL 已确认
- [ ] 工作负载、内部链路与公网入口就绪
- [ ] Web 应用从真实入口可达；需要时登录或初始化后核心流程可用
- [ ] 已审阅 init、迁移、启动与运行时日志
- [ ] 无 `no matching manifest`、`no match for platform in manifest` 或 `exec format error`
- [ ] 稳定窗口：告警、重启、OOM、就绪状态已收敛
- [ ] 数据库、对象存储、worker 与 cron 任务表现符合预期核心行为

### 2. 失败处理

**复用第三方镜像的架构不匹配：** 有可构建源码时，在 Phase 2–4 修复镜像与模板，重新从 Phase 5 部署。无可构建源码时，报告不兼容服务、镜像与错误。不得猜测其他镜像或浮动标签。

**资源耗尽：** OOMKilled、重启循环、迁移超时或就绪抖动表示当前资源无法通过运行验收。将 CPU 或内存提高到下一 Sealos 步长，重新生成模板，从 Phase 5 重新部署并重新运行 Phase 7。官方模板路径不能编辑已验证官方 YAML；资源无法通过时禁用复用并返回标准路径。

### 3. 状态记录

全部适用检查通过后，按 [状态与完成](/pipeline/state-and-completion) 写入 `.sealos/state.json` 并通过 schema 验证。更新桥接持久化（如适用）。

## 停止条件

| 结果 | 条件 |
| --- | --- |
| **STOP** | 有界补救后必需运行检查仍失败 |
| **COMPLETE** | 所有适用检查通过且 `state.json` 已落盘 |

## 验收标准

- 真实入口、核心行为、日志与稳定性对当前工作负载通过
- 触发时已走完资源补救循环
- `state.json` 已写入并通过 schema 验证
