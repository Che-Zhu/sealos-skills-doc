## 目的

Phase 5 仅属于标准构建路径。它根据 `deployment-plan.json` 判断是否需要先构建镜像，再读取 `analysis.json` 中的清单与部署源事实，产出含不可变镜像 digest 的完整 Sealos 模板。

当前实现不读取相似模板或目录 YAML。模板须遵循当前项目事实与转换规则。

## 入口分支

读取 `deployment_plan` 与 `deployment-plan.json`。按容器工作负载判断：

| 情况 | 行为 |
| --- | --- |
| 每个容器工作负载均有可复用 digest | 跳过 Phase 4，继续本 Phase 模板生成 |
| 一个或多个服务须构建 | **CONTINUE → Phase 4**；Phase 4 完成后返回本 Phase |

## 输入

| 输入 | 来源 |
| --- | --- |
| `analysis.json` | Phase 0–2 |
| `deployment-plan.json` | Phase 2（经 `analysis.json` → `deployment_plan`） |
| 构建结果 | Phase 4（若本 Phase 入口分支曾进入 Phase 4） |
| 部署源文件 | `.sealos/deployment-source/`（Phase 5 按需生成） |

## 输出

| 输出 | 路径 | 说明 |
| --- | --- | --- |
| Canonical 模板 | `.sealos/template/index.yaml` | 供 5.5、6 与恢复使用的单一模板 |
| 资源映射 | `.sealos/deployment-source/resource-map.json` | 源到输出的对账 |
| 拓扑证据 | `.sealos/topology-evidence/{app-name}.yaml` | 仅校验器使用 |

## 转换路径

| 源类型 | 方法 |
| --- | --- |
| Compose | 确定性转换器 `--dry-run`；Phase 4 digest 的逐服务镜像覆盖 |
| Helm | chart 副本上 `helm template`；适配器保留渲染资源 |
| Kubernetes | 源适配器保留资源并转换不支持字段 |
| 隐式 | AI 从已确认服务与 digest 构造临时 Compose 输入 |

适配器是优选工具，不是资格门槛。适配器无法表达项目时，Agent 可修复临时输入或生成等价 canonical 模板。须通过相同质量门，不得丢弃服务或绕过校验。

## 网络与端口

- `ports` → 公网入口候选
- `expose` → 仅内部 Service
- 一个公网候选自动选定；多个候选从 Ingress、README、角色或 `.sealos/config.json` 的 `public_service` 解析
- 内部服务引用重写为 Kubernetes Service FQDN

## 镜像与 pull secret

最终容器镜像须为 `repository@sha256:...`。pull-secret 引用仅当 Phase 4 对该 service key 报告 `ghcr_secret_required` 或 `indeterminate`。

## 数据库

优先级：

1. 声明外部数据库 → 保留外部连接
2. 支持的服务 DB 且无外部意图 → KubeBlocks 默认
3. 嵌入式 SQLite → 保留在应用内
4. 不支持或 KubeBlocks 非无损转换 → 保留源工作负载并附 `docker-to-sealos.kubeblocks-fallback-reason`

## 资源下限

按组件角色（业务主服务、sidecar/init/job、KubeBlocks 组件）的硬性最低值。AI 可根据项目证据提高限制。质量门强制执行下限与有效 Sealos 资源步长。

## 停止条件

| 结果 | 条件 |
| --- | --- |
| **STOP** | `index.yaml` 质量门失败 |
| **CONTINUE → Phase 5.5** | 模板通过完整质量门 |

继续前须重新生成并重新运行完整质量门。不允许部分修复。

## 验收标准

- `.sealos/template/index.yaml` 存在
- 所有最终镜像为 digest 固定
- 完整拓扑保留于资源映射
- 质量门通过已记录
