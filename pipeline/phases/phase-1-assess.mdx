## Purpose

Phase 1 understands the deployment shape the repository can reasonably take. It scores cloud-native readiness and records confirmed project facts for later phases.

The repository is the source boundary, not the only deployable unit. The agent must not assume only the repo root is deployable. The agent must not stop because the root is a library, component package, or monorepo. Apps, doc sites, static sites, Storybook, and examples supported by source, README, workspace scripts, or CI are valid deployment shapes.

### Entry judgment

At the start, the agent makes an internal judgment: is the project certainly unable to run on Sealos in any reasonable way?

| Result | Action |
| --- | --- |
| Certain impossibility | State one short specific reason, then **STOP** |
| Any uncertainty | Continue assess with no separate output |

Example stop: a native desktop app with no online runtime and no reasonable container path. CLI, library, low score, missing entry, or weak evidence alone must not stop Phase 1.

This judgment produces no artifact, score, report, candidate list, or user confirmation. UPDATE mode skips Phase 1 because mode detection already confirmed a running app.

Phase 1 is not a language, framework, or app-type support list. It records facts and risks. It must not stop because of unknown language, static files, unknown framework, missing package manager, missing runtime version, missing root start command, or unidentified port.

## Outputs

| Output | Path | Description |
| --- | --- | --- |
| Analysis snapshot | `.sealos/analysis.json` | Facts, score, inventories for later phases |

`analysis.json` includes:

- Project source, work directory, repository, and branch
- Readiness score 0–12 with breakdown and risks
- Language, framework, package manager, runtime, ports, databases, env vars, container facts
- Image inventory and service inventory placeholders for Phase 2

`analysis.json` is a fact snapshot, not deploy permission. Low score, empty descriptive fields, missing root entry, or unfamiliar app types record risk and continue.

## Preconditions

- Phase 0 passed
- First-deploy path (not UPDATE)

## Procedure

The agent reads project evidence. It must not guess or invent default values for unknown facts.

The readiness detector supplies repository signals only. It does not decide deployment target, runtime shape, or whether to continue. The agent combines source, docs, workspace, and CI. Missing detector output does not mean the capability is absent.

The agent records:

- Language, framework, package manager, runtime version
- Start method, service ports, database dependencies
- Existing container configuration
- Environment variable classification
- Stateless design, externalized config, scaling, lifecycle, observability, service boundaries
- Cloud-native readiness score 0–12

Language and package manager use open strings. Static projects may record `html`, `css`, `javascript`, `nginx`. Unknown values use `null`, `[]`, or `{}`.

Hard requirements belong to later phases. Phase 3 needs a build path only for services it builds. Phase 5 needs a container port only when it creates network ingress.

## Stop conditions

| Result | Condition |
| --- | --- |
| **STOP** | Agent is certain the project cannot run on Sealos |
| **CONTINUE** | Any uncertainty or positive assess → Phase 1.5 |
