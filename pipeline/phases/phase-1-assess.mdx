## 目的

读取 `analysis.json` 中的 `work_dir` 证据，补充 [Phase 0](/pipeline/phases/phase-0-preflight) 写入的字段，记录已确认的项目事实。

UPDATE 模式跳过 Phase 1。

不得评分，不得选择镜像，不得生成模板，不得创建云端资源。

## 入口判断（黑名单）

采用黑名单模式。Agent 自行判断是否满足黑名单定义。

**黑名单定义（须同时满足）：**

1. 项目本身无法以云服务形式运行。
2. 仓库内没有任何部分可以以云服务形式部署。

仅当两项均 **100% 确认** 时 **STOP**。任一项不能 100% 确认时 **CONTINUE**。不得因不确定或证据不足而 STOP。

| 结果 | 条件 |
| --- | --- |
| **STOP** | 黑名单定义两项均 100% 确认 |
| **CONTINUE** | 其余所有情况 |

仓库是来源边界。

此判断不产生产物或用户提示。不能 100% 确认时直接继续事实采集。

## 输入

| 输入 | 来源 | 必须 |
| --- | --- | --- |
| `analysis.json` | [Phase 0](/pipeline/phases/phase-0-preflight) | 是 |

Phase 0 须已写入 `runtime_profile`、`work_dir`、`repo_name`。`github_url` 可为 `null`。

Phase 1 从 `analysis.json` 的 `work_dir` 读取项目文件。不得要求上阶段未写入的字段。

## 输出

| 输出 | 路径 |
| --- | --- |
| 分析快照 | `.sealos/analysis.json` |

写入语言、框架、端口、数据库、环境变量、容器事实、镜像与服务清单占位，以及已确认的风险备注。

`analysis.json` 是事实快照，不是部署许可。字段为空或存在风险时记录并继续。

未知事实写 `null`、`[]` 或 `{}`。不得编造默认值。

## 前置条件

- [Phase 0](/pipeline/phases/phase-0-preflight) 已通过，且 `.sealos/analysis.json` 含 `runtime_profile`、`work_dir`、`repo_name`
- [部署模式识别](/pipeline/mode-detection) 结果为 **DEPLOY**

## 流程

### 1. 读取已有 `analysis.json`

读取 `.sealos/analysis.json`。保留 `runtime_profile`、`work_dir`、`repo_name`、`github_url`，不得修改。

### 2. 采集事实

读取 README、依赖清单、Dockerfile、CI 配置、应用子目录。

记录：

- 语言、框架、包管理器、运行时版本
- 部署形态、服务边界、端口
- 数据库依赖、环境变量（标注 `auto` / `required` / `optional`）
- `has_dockerfile`、复杂度层级
- 已确认风险（缺失入口、非常见运行时、证据冲突等）

检测器或脚本输出是参考信号，不是支持列表。无输出不代表能力缺失。

### 3. 写入 `analysis.json`

在已有文件上补充字段。保留 Phase 0 写入的 `runtime_profile`、`work_dir`、`repo_name`、`github_url`。符合 [analysis schema](/specs/artifact-schemas) 后写入。

## 停止条件

| 结果 | 条件 |
| --- | --- |
| **STOP** | 黑名单定义两项均 100% 确认 |
| **CONTINUE** | 其余情况 → [Phase 1.5](/pipeline/phases/phase-1-5-template) |

## 验收标准

- `.sealos/analysis.json` 存在且通过 schema 校验
- 黑名单定义已按两项条件核对
- `runtime_profile`、`work_dir`、`repo_name`、`github_url` 未被修改
- 未知事实无编造值
- 未写入评分或就绪度分数字段
