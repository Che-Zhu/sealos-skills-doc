## 目的

读取 `WORK_DIR` 证据，记录项目事实，评分云原生就绪度，写入 `.sealos/analysis.json`。

UPDATE 模式跳过 Phase 1。

不得选择镜像，不得生成模板，不得创建云端资源。

## 入口判断（黑名单）

采用黑名单模式。Agent 自行判断是否满足黑名单定义。

**黑名单定义（须同时满足）：**

1. 项目本身无法以云服务形式运行。
2. 仓库内没有任何部分可以以云服务形式部署。

仅当两项均 **100% 确认** 时 **STOP**。任一项不能 100% 确认时 **CONTINUE**。不得因不确定、低分或证据不足而 STOP。

| 结果 | 条件 |
| --- | --- |
| **STOP** | 黑名单定义两项均 100% 确认 |
| **CONTINUE** | 其余所有情况 |

仓库是来源边界。

此判断不产生产物、分数或用户提示。不能 100% 确认时直接继续评分。

## 输入

| 输入 | 来源 | 必须 |
| --- | --- | --- |
| `WORK_DIR` | [运行入口](/pipeline/entry) | 是 |
| `WORK_DIR_IS_TEMP` | [运行入口](/pipeline/entry) | 是 |
| `runtime_profile` | [Phase 0](/pipeline/phases/phase-0-preflight) | 是 |
| `REPO_NAME` | [运行入口](/pipeline/entry) | 是 |
| `GITHUB_URL` | [运行入口](/pipeline/entry) | 否 |

Phase 1 从 `WORK_DIR` 读取项目文件。不得要求上阶段未写入的字段。

## 输出

| 输出 | 路径 |
| --- | --- |
| 分析快照 | `.sealos/analysis.json` |

写入项目来源、就绪度分数（0–12）、语言、框架、端口、数据库、环境变量、容器事实、镜像与服务清单占位。

`analysis.json` 是事实快照，不是部署许可。低分或字段为空时记录风险并继续。

未知事实写 `null`、`[]` 或 `{}`。不得编造默认值。

## 前置条件

- [Phase 0](/pipeline/phases/phase-0-preflight) 已通过
- [运行入口](/pipeline/entry) 已完成
- [部署模式识别](/pipeline/mode-detection) 结果为 **DEPLOY**

## 流程

### 1. 创建产物目录

```bash
mkdir -p "$WORK_DIR/.sealos"
```

### 2. 评分

若 Node.js 可用：

```bash
node "<SKILL_DIR>/scripts/score-model.mjs" "$WORK_DIR"
```

若 Node.js 不可用，按 `cloud-native-readiness/knowledge/criteria.md` 手动评分。

分数低于 4 时警告用户并继续。分数不授权 STOP。

### 3. 补充事实

读取 README、依赖清单、Dockerfile、CI 配置、应用子目录。

记录：

- 语言、框架、包管理器、运行时版本
- 部署形态、服务边界、端口
- 数据库依赖、环境变量（标注 `auto` / `required` / `optional`）
- `has_dockerfile`、复杂度层级

检测器输出是参考信号，不是支持列表。检测器无输出不代表能力缺失。

### 4. 写入 `analysis.json`

符合 [analysis schema](/specs/artifact-schemas) 后写入。

## 停止条件

| 结果 | 条件 |
| --- | --- |
| **STOP** | 黑名单定义两项均 100% 确认 |
| **CONTINUE** | 其余情况 → [Phase 1.5](/pipeline/phases/phase-1-5-template) |

## 验收标准

- `.sealos/analysis.json` 存在且通过 schema 校验
- 黑名单定义已按两项条件核对
- 未知事实无编造值
