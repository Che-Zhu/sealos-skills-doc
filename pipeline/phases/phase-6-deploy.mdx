## 目的

Phase 6 接受 Phase 1.5 的官方模板或 Phase 5 生成的模板。

官方模板路径：收集必填输入并展示可选默认。不重写官方 YAML，不重建当前源码。

## 输入

| 输入 | 来源 |
| --- | --- |
| 模板 | `.sealos/template/index.yaml` |
| 模板输入 | Phase 5.5 或 Phase 6 收集 |
| Namespace | Phase 0（`local`） |

## 输出

| 输出 | 说明 |
| --- | --- |
| 线上资源 | App、工作负载、网络、存储、依赖 |
| `APP_NAME` | 来自安全白名单响应或唯一线上发现 |
| Pull secret | 私有 GHCR 镜像需要时 |

## 流程

1. 从 Phase 0 准备的 kubeconfig 读取 namespace。为空、无效或与工作空间不匹配则停止。不得回退到 `default`。
2. 用最终模板与输入运行部署预检。不创建资源。
3. 预检成功后提交一次真实创建请求。预检与创建使用相同模板字节与参数。
4. 从白名单响应或唯一线上 Instance 匹配提取 `APP_NAME`。
5. 需要时在同一 namespace 创建应用 pull secret。
6. 等待 rollout、Job、CronJob 与 operator 管理资源。
7. 访问 Ingress 或 App URL 前等待公网 Service Endpoints。
8. 工作负载未就绪时读取 Pod 状态、事件与日志。

创建超时或 5xx 返回 unknown 时，不得自动重试或用 kubectl 回退创建。只读检查近期 Instance 与 App 范围。仅在唯一匹配时继续。

API 成功表示资源存在，不表示应用可用。Phase 6.5 为必需。

## 停止条件

| 结果 | 条件 |
| --- | --- |
| **STOP** | namespace 无效、预检失败、secret 创建失败、unknown 创建且无唯一匹配 |
| **CONTINUE → Phase 6.5** | 资源已创建且 rollout 等待完成 |

## 验收标准

- 预检与创建使用相同模板与输入
- `APP_NAME` 安全解析
- 需要时在读就绪检查前创建 pull secret
