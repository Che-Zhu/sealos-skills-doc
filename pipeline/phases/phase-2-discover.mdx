## 目的

确定本仓库一次 Sealos 部署的完整运行时拓扑与构建方式，产出 `deployment-plan.json`。

一次 Sealos 部署对应**整仓一张模板**。计划须覆盖全部相关服务（含数据库、队列、worker），不得只写主应用。

不得在本阶段实际构建或推送镜像。不得生成 Sealos 模板。不得创建云端资源。不得根据 `official_template` 选定部署源或修改 `official_template` 字段。

UPDATE 模式跳过本 Phase。

## 输入

| 输入 | 来源 |
| --- | --- |
| `analysis.json` | Phase 0、Phase 1 |
| 项目源码与文档 | `analysis.json` → `work_dir` |
| `railpack` | Phase 0 已安装（`sandbox` 预装，`local` 须可用） |
| `gitingest` | Phase 0 已安装 |

## 输出

| 输出 | 路径 | 说明 |
| --- | --- | --- |
| 部署相关摘要 | `.sealos/phase-2/gitingest-digest.txt` | gitingest 输出（范围见步骤 2） |
| 部署计划 | `.sealos/phase-2/deployment-plan.json` | Subagent 产出；JSON 构建与部署指南 |
| `analysis.json` | `.sealos/analysis.json` | 含 `deployment_plan` 指向上述文件；Phase 3、4 所需字段 |

`deployment-plan.json` 字段级契约待定。计划至少须描述完整服务拓扑、各服务镜像或构建方式，并附证据路径。

部署源类型见 [部署源](/pipeline/deployment-sources)。

## 前置条件

- Phase 1 出口为 **CONTINUE → Phase 2**（标准路径）

## 流程

### 1. 读取 `analysis.json`

读取 `work_dir`、`runtime_profile` 等。保留 Phase 0 与 Phase 1 已写字段，不得修改 `official_template`。

### 2. 主 Agent 侦察

阅读根目录 `README*`、`CONTRIBUTING*` 等。在 `work_dir` 运行 `gitingest`，ingest 部署与 CI 证据，不得 ingest 全仓源码。输出写入 `.sealos/phase-2/gitingest-digest.txt`。

须包含的文件类型示例：

- `README*`、`CONTRIBUTING*`
- `docker-compose*`、`compose.y*ml`、`Dockerfile*`
- `Chart.yaml`、Helm `values*.yaml`、`**/templates/**`
- `**/k8s/**`、`**/deploy/**`、Kubernetes 清单
- `Makefile`、`Procfile`、`fly.toml`、`render.yaml` 等 PaaS 或脚本化部署配置
- `package.json`、`pnpm-workspace.yaml`、`turbo.json`、`nx.json`、`go.work`、`Cargo.toml`、`pyproject.toml` 等工作区线索
- `.github/workflows/**` 及其他 CI 配置

将 README 理解与侦察要点写入部署日志（自然语言，数句即可）。

### 3. Subagent — 部署计划

主 Agent 启动一个 Subagent。传入：

- `analysis.json`
- `.sealos/phase-2/gitingest-digest.txt` 路径
- 主 Agent 口头交接（发现与判断，自然语言）

告知 Subagent：**需要一份能用于构建并部署本项目的 JSON 计划**；须自行探索仓库；`railpack` 可用（`info`、`plan`）；产出写入 `.sealos/phase-2/deployment-plan.json`。

Subagent 自行决定探索方式与是否运行 railpack。不得从组织或仓库名猜测已发布镜像。

### 4. 写入 `analysis.json`

```json
{
  "deployment_plan": ".sealos/phase-2/deployment-plan.json"
}
```

与 Phase 0、Phase 1 已有字段合并写入。根据 `deployment-plan.json` 补充 Phase 3、4 所需字段（如 `deployment_source`、`service_inventory`、`image_inventory`）。未知写 `null`、`[]` 或 `{}`。不得编造。

通过 [schema](/specs/artifact-schemas) 后落盘。

## 停止条件

| 结果 | 条件 |
| --- | --- |
| **STOP** | Subagent 无法产出覆盖全部相关服务的可信 `deployment-plan.json` |
| **STOP** | `deployment-plan.json` 或 `analysis.json` 无法写入或通过 schema |
| **CONTINUE → Phase 4** | 计划与 `analysis.json` 已落盘 |

Phase 3 构建定义失败时，可返回 Phase 2 步骤 3 修订 `deployment-plan.json`。

## 验收标准

- `deployment-plan.json` 存在且覆盖全部相关服务
- `analysis.json` 含 `deployment_plan` 且路径正确
- `analysis.json` 通过 schema
