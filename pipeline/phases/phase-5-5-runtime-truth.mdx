## 目的

运行事实验收从线上云状态判断成功，不仅凭模板输出或 API 返回码。

Phase 5.5 对每次部署为必需。创建资源而无运行验收不算部署成功。

## 输入

| 输入 | 来源 |
| --- | --- |
| 线上资源 | Phase 5 |
| 访问 URL | Ingress、App URL、内部端点 |
| 工作负载状态 | Pod、事件、日志 |

## 输出

| 输出 | 路径 | 说明 |
| --- | --- | --- |
| 已验证部署 | — | 仅检查通过后向用户报告成功 |
| 更新状态 | `.sealos/state.json` | 在 [状态与完成](/pipeline/state-and-completion) 中写入 |

## 验收清单

Agent 须按工作负载类型验证适用项：

- [ ] App、工作空间、资源范围与访问 URL 已确认
- [ ] 工作负载、内部链路与公网入口就绪
- [ ] Web 应用从真实入口可达；需要时登录或初始化后核心流程可用
- [ ] 已审阅 init、迁移、启动与运行时日志
- [ ] 无 `no matching manifest`、`no match for platform in manifest` 或 `exec format error`
- [ ] 稳定窗口：告警、重启、OOM、就绪状态已收敛
- [ ] 数据库、对象存储、worker 与 cron 任务表现符合预期核心行为

## 失败处理

**复用第三方镜像的架构不匹配：** 有可构建源码时，在 Phase 2–3 构建 `linux/amd64`，更新模板，重新部署并重新运行 Phase 5.5。无可构建源码时，报告不兼容服务、镜像与错误。不得猜测其他镜像或浮动标签。

**资源耗尽：** OOMKilled、重启循环、迁移超时或就绪抖动表示当前资源无法通过运行验收。将 CPU 或内存提高到下一 Sealos 步长，重新生成相同模板，重新部署并重新运行 Phase 5.5。官方模板路径不能编辑已验证官方 YAML；资源无法通过时禁用复用并返回标准路径。

## 停止条件

| 结果 | 条件 |
| --- | --- |
| **STOP** | 有界补救后必需运行检查仍失败 |
| **CONTINUE → 状态记录** | 所有适用检查通过 |

## 验收标准

- 真实入口、核心行为、日志与稳定性对当前工作负载通过
- 触发时已走完资源补救循环
- 可写入 `state.json` 并通过 schema 验证
