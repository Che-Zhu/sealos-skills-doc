## 目的

Phase 4 属于标准构建路径。它读取 `deployment-plan.json` 的 `deployment_source`，**统一固定全部容器镜像 digest**，再生成 `.sealos/template/index.yaml`。

[Phase 1](/pipeline/phases/phase-1-assess) 官方模板快速路径跳过本 Phase。

不得创建云端资源。不得推送镜像。不得修改 `deployment_source`（无效时 **RETURN → Phase 2**）。

## 前置条件

- Phase 2 已写入 `deployment_plan` 与 `deployment-plan.json`
- `deployment_source` 可读（见 [部署源](/pipeline/deployment-sources)）

## 阶段约束

进入本 Phase 时须知晓，并在**执行过程中**遵守。

| ID | 约束 | 说明 |
| --- | --- | --- |
| P4-01 | 不得创建云端资源、不得推送镜像 | |
| P4-02 | 不得修改 `deployment_source` | 无效时 **RETURN → Phase 2** |
| P4-03 | 不得将 digest 写入 `build-result.json` | digest 表只写在 `image-digests.json` |
| P4-04 | 须固定部署源中的**每一个**容器镜像 digest | 含上游 `image:` 与本仓库构建 |
| P4-05 | 部署门禁只跑 `check_consistency.py` 规则子集 | 不得跑 `quality_gate.py` 全量 CI |

## 阶段验收

Phase 4 **产出落盘后**运行：

```bash
node skills/sealos-deploy/scripts/validate-phase-4.mjs --dir "$WORK_DIR"
```

脚本核对：

| ID | 核对项 |
| --- | --- |
| P4-V01 | `image-digests.json` 每项为 `repository@sha256:...`（`linux/amd64`） |
| P4-V02 | 模板中每个容器 `image` 与 digest 表一致 |
| P4-V03 | `build-result.json` 的 `pushed` 不含 `@sha256:` |
| P4-V04 | 模板通过部署门禁 |

未通过 → 不得 **CONTINUE → Phase 5**。

## 输入

| 文件 | 说明 |
| --- | --- |
| `.sealos/analysis.json` | 指针入口 |
| `.sealos/phase-2/deployment-plan.json` | 含 `deployment_source` |
| `.sealos/phase-3/build-result.json` | 有构建时：`pushed` 与 `pull_access` |

## 输出

| 输出 | 路径 |
| --- | --- |
| Sealos 模板 | `.sealos/template/index.yaml` |

Phase 6 部署使用上表文件。其余写入 `.sealos/phase-4/`，**不是** Sealos 模板：

| 中间产物 | 路径 | 用途 |
| --- | --- | --- |
| 镜像 digest 表 | `.sealos/phase-4/image-digests.json` | 全部工作负载的 `repository@sha256:...` |
| 源快照 | `.sealos/phase-4/source/` | 可转换的部署源副本 |
| Helm 渲染 | `.sealos/phase-4/rendered.yaml` | Helm 路径：`helm template` 输出 |
| 资源映射 | `.sealos/phase-4/resource-map.json` | 源工作负载与模板资源的对账 |

## 流程

### 1. 进入与恢复

- 若 `.sealos/template/index.yaml` 已存在 → 按 [中断恢复](/pipeline/mode-detection#中断恢复) 处理。
- 否则从步骤 2 继续。

### 2. 准备中间产物

在 `.sealos/phase-4/source/` 留下可转换快照。不重新侦察仓库。

| 源类型 | 动作 |
| --- | --- |
| Compose | 复制 `deployment_source` 至 `source/` |
| Helm | 复制 chart 至 `source/`；`helm template` → `.sealos/phase-4/rendered.yaml` |
| Kubernetes | 复制 manifest 至 `source/` |

完成后，若须构建且尚无 `build_result`（未完成推送）→ **CONTINUE → Phase 3**（返回后从步骤 3 继续）。

### 3. 统一固定镜像 digest

从部署源（及步骤 2 快照）枚举**每一个**容器镜像引用。工作负载 key 与部署源一致。每项须解析为 `repository@sha256:...` 且支持 `linux/amd64`。

| 镜像来源 | 解析输入 |
| --- | --- |
| 本仓库构建 | `build-result.json` → `pushed` 中的 tag 引用 |
| 上游 `image:` | 部署源中的 tag 引用 |

将完整结果写入 `.sealos/phase-4/image-digests.json`（契约见 [产物 Schema](/specs/artifact-schemas)）。**不得**将 digest 写回 `build-result.json`。

解析失败（registry 不可达、无 `linux/amd64`、私有库无凭证）→ **STOP**。

### 4. 转换

按 `deployment_source` 类型转换；使用 `image-digests.json` 覆盖每个工作负载的 `image`：

| 类型 | 转换 |
| --- | --- |
| Compose | `compose_to_template.py`（默认 `--kompose-mode always`）；`--image-override` 逐服务 |
| Helm | 读 `rendered.yaml` → 适配器；按 key 替换 `image` |
| Kubernetes | 适配器；按工作负载名替换 `image` |

不得丢弃服务。写入 `.sealos/phase-4/resource-map.json` 与 `.sealos/template/index.yaml`。

### 5. 部署门禁

对 `.sealos/template/index.yaml` 运行 [部署门禁](/specs/template-format#部署门禁)（`check_consistency.py` 规则子集）。**不得**运行 `quality_gate.py` 全量 CI。失败 → **STOP**。修复后从步骤 3 重新固定 digest、重新转换并全量重跑门禁。

### 6. 下游

通过 → **CONTINUE → [Phase 5](/pipeline/phases/phase-5-prepare)** → Phase 6 → Phase 7。

## 转换约束

**网络：** `ports` 为公网候选；`expose` 为内部 Service。多候选时从 Ingress、README、角色或 `.sealos/config.json` 的 `public_service` 解析。内部引用重写为 Service FQDN。

**Pull secret：** 仅当 `build-result.json` 中该 key 的 `pull_access` 为 `ghcr_secret_required`。

**数据库：** 外部声明 → 保留外部；支持的服务 DB → KubeBlocks；SQLite → 保留在应用内；否则保留源工作负载并附 `docker-to-sealos.kubeblocks-fallback-reason`。

**资源：** 业务 workload 的 limits 尽量使用平台资源阶梯，并由 limits 推导 requests（R038）。新建 KubeBlocks `Cluster` 时尽量添加 dbprovider 可见性 labels（R040）。官方模板可不满足；门禁不校验这两条。见 [资源下限](/specs/resource-floors)。

**资源下限（门禁）：** 数据库组件仍须满足 R019；见 [部署门禁](/specs/template-format#部署门禁)。

## 停止条件

| 结果 | 条件 |
| --- | --- |
| **CONTINUE → Phase 3** | 须构建且尚未推送（无 `build_result`） |
| **CONTINUE → Phase 5** | 部署门禁通过 |
| **RETURN → Phase 2** | 部署源无效（缺 Dockerfile、坏 context、拓扑残缺） |
| **STOP** | digest 解析失败、转换失败、或部署门禁失败 |

## 验收标准

- `.sealos/phase-4/image-digests.json` 覆盖部署源全部容器镜像且均为 `repository@sha256:...`（`linux/amd64`）
- `.sealos/template/index.yaml` 存在且部署门禁通过
- `.sealos/phase-4/resource-map.json` 拓扑完整
