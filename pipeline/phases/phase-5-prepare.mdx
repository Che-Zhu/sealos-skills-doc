## 目的

Phase 5 在部署前收集模板输入、记录用户确认，并对最终 YAML 运行 dry-run。

不得创建云端资源。不得改写 `.sealos/template/index.yaml` 中的官方模板内容。

## 前置条件

- `.sealos/template/index.yaml` 已存在（[Phase 1](/pipeline/phases/phase-1-assess) 拉取官方模板，或 [Phase 4](/pipeline/phases/phase-4-template) 生成）
- 文件缺失 → 回到上游 Phase，不得进入本 Phase

## 阶段约束

进入本 Phase 时须知晓，并在**执行过程中**遵守。

| ID | 约束 | 说明 |
| --- | --- | --- |
| P5-01 | 不得创建云端资源 | dry-run 不创建资源 |
| P5-02 | 不得改写 `.sealos/template/index.yaml` 中的官方模板内容 | 只收集输入与确认 |
| P5-03 | 模板文件须已由 Phase 1 或 Phase 4 写入 | 缺失则回到上游 Phase |
| P5-04 | 须获用户明确部署确认 | 未确认不得进入 Phase 6 |

## 阶段验收

Phase 5 **产出落盘后**运行：

```bash
node skills/sealos-deploy/scripts/validate-phase-5.mjs --dir "$WORK_DIR"
```

脚本核对：

| ID | 核对项 |
| --- | --- |
| P5-V01 | `.sealos/template/index.yaml` 存在 |
| P5-V02 | `.sealos/phase-5/prepare-result.json` 通过 schema |
| P5-V03 | `template_sha256` 与当前模板文件一致 |
| P5-V04 | `dry_run` 为 `passed` 且 `user_confirmed` 为 `true` |

未通过 → 不得 **CONTINUE → Phase 6**。

## 输入

| 输入 | 来源 |
| --- | --- |
| 模板 | `.sealos/template/index.yaml` |
| 用户覆盖 | 存在时的 `.sealos/config.json` |
| Namespace | Phase 0（`local`） |

## 输出

| 输出 | 说明 |
| --- | --- |
| 最终输入集 | 供 [Phase 6](/pipeline/phases/phase-6-deploy) 使用 |
| 用户确认 | 明确的部署批准 |
| dry-run 通过 | 未创建资源 |
| 准备结果 | `.sealos/phase-5/prepare-result.json` |

## 流程

### 1. 收集配置

将模板字段分为四组：

| 组 | 示例 |
| --- | --- |
| 自动管理 | 应用名、内部 URL、随机秘密、托管基础设施连接 |
| 用户必填 | 管理员账号、API 密钥、SMTP、OAuth 凭证 |
| 可选 | 有默认的功能开关与运行时参数 |
| 固定 | 生产模式、内部端口、路径 |

1. 说明必填字段。
2. 收集必填值。
3. 提供可选修改。
4. 在日志与摘要中掩码敏感值。

### 2. 校验与 dry-run

1. 校验绑定输入后的最终模板。
2. 用最终模板与输入对 Sealos 部署 API 运行 YAML dry-run。不创建资源。
3. 展示区域、镜像、依赖与配置摘要。
4. 等待明确部署确认。

5. 写入 `.sealos/phase-5/prepare-result.json`（`template_sha256`、`dry_run`、`user_confirmed`）。

dry-run 通过且用户确认后 → **CONTINUE → Phase 6**。

## 停止条件

| 结果 | 条件 |
| --- | --- |
| **STOP** | 用户拒绝部署 |
| **STOP** | 模板校验失败或 dry-run 失败 |
| **CONTINUE → Phase 6** | 用户确认且 dry-run 通过 |

## 验收标准

- 必填输入已收集
- 敏感值在日志中已掩码
- dry-run 与 Phase 6 使用相同模板字节与参数
