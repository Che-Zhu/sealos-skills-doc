## 目的

判定当前环境能否运行 `sealos-deploy`。

不得解析项目来源，不得物化源码，不得判断可部署性，不得构建镜像，不得生成模板，不得创建云端资源，不得写入 `.sealos/`。

## 输入

| 输入 | 来源 |
| --- | --- |
| `SEALAI_DEPLOY_TASK_ID` | 进程环境变量 |
| 主机环境 | OS、包管理器 |

## 输出

| 输出 | 说明 |
| --- | --- |
| `runtime_profile` | `local` 或 `sandbox` |
| 结果 | `CONTINUE` 或 `STOP` |

## 前置条件

无。

## 流程

### 1. 判定 `runtime_profile`

| `SEALAI_DEPLOY_TASK_ID` | `runtime_profile` |
| --- | --- |
| 存在 | `sandbox` |
| 不存在 | `local` |

### 2. 安装必装依赖

调用本 skill 即表示用户同意安装依赖。缺失则立即安装或升级，不得逐项询问用户。安装后重新核对。

**`local` 与 `sandbox` 共用：**

Git、Git LFS、Node.js 18+、Python 3.8+ 与 PyYAML、kompose、Helm 3+、kubectl、curl、jq

**仅 `local` 额外：**

`gh`、Docker CLI、运行中的 Docker daemon、Docker Buildx

若 Docker 已安装但 daemon 未运行，启动 daemon。

**仅 `local` 认证：**

若 `gh` 未登录或缺少 `write:packages`，完成登录或授权。核对所选工作空间的 kubeconfig。

### 3. 核对平台上下文（仅 `local`）

1. 选择 Sealos Cloud 区域。
2. 完成 Sealos 登录。
3. 选择目标工作空间。

更新用户目录中的 Sealos auth 与 kubeconfig。

`sandbox` 跳过本节。Kubernetes 权限、`GITHUB_TOKEN`、S3 等注入物在后续阶段按需核对。

## 停止条件

| 结果 | 条件 |
| --- | --- |
| **STOP** | 无法判定 `runtime_profile` |
| **STOP** | 必装依赖无法安装或核对失败 |
| **STOP** | `local`：区域、登录或工作空间未确认 |
| **CONTINUE** | 全部通过 → [运行入口](/pipeline/entry) |

## 验收标准

- `runtime_profile` 为 `local` 或 `sandbox`
- 必装依赖已安装且可用
- `local`：Sealos 区域、登录与工作空间已确认
