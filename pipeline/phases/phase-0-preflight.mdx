## 目的

判定当前环境能否运行 `sealos-deploy`。解析项目来源，物化源码，将 `runtime_profile`、`work_dir`、`repo_name`、`github_url` 写入 `.sealos/analysis.json`。

不得判断可部署性，不得构建镜像，不得生成模板，不得创建云端资源。

## 输入

| 输入 | 来源 |
| --- | --- |
| `SEALAI_DEPLOY_TASK_ID` | 进程环境变量 |
| 主机环境 | OS、包管理器 |
| 项目来源 | skill 调用参数：GitHub URL、本地路径；无参数时使用 `$(pwd)` |

## 输出

| 输出 | 说明 |
| --- | --- |
| `.sealos/analysis.json` | 含 `runtime_profile`、`work_dir`、`repo_name`、`github_url` |
| 部署日志 | 从本阶段起记录阶段边界 |
| 结果 | `CONTINUE` 或 `STOP` |

## 前置条件

无。

## 流程

### 1. 判定 `runtime_profile`

| `SEALAI_DEPLOY_TASK_ID` | `runtime_profile` |
| --- | --- |
| 存在 | `sandbox` |
| 不存在 | `local` |

### 2. 安装必装依赖

调用本 skill 即表示用户同意安装依赖。缺失则立即安装或升级，不得逐项询问用户。安装后重新核对。

**`local` 与 `sandbox` 共用：**

Git、Git LFS、Node.js 18+、Python 3.8+ 与 PyYAML、[gitingest](https://pypi.org/project/gitingest/)（`pip install gitingest`）、kompose、Helm 3+、kubectl、curl、jq

**仅 `local` 额外：**

`gh`、Docker CLI、运行中的 Docker daemon、Docker Buildx、[railpack](https://github.com/railwayapp/railpack)

`sandbox` 环境已预装 railpack。`local` 须安装或升级 railpack 并核对 `railpack --help` 可用。

若 Docker 已安装但 daemon 未运行，启动 daemon。

**仅 `local` 认证：**

若 `gh` 未登录或缺少 `write:packages`，完成登录或授权。核对所选工作空间的 kubeconfig。

### 3. 核对平台上下文（仅 `local`）

1. 选择 Sealos Cloud 区域。
2. 完成 Sealos 登录。
3. 选择目标工作空间。

更新用户目录中的 Sealos auth 与 kubeconfig。

`sandbox` 跳过本节。Kubernetes 权限、`GITHUB_TOKEN`、S3 等注入物在后续阶段按需核对。

### 4. 解析项目来源

| 来源 | 行为 |
| --- | --- |
| GitHub 仓库 URL | 克隆到临时目录 |
| 本地项目目录 | 使用指定路径 |
| 无参数 | 使用 `$(pwd)` |

解析 `repo_name`。若存在 GitHub 远程，记录 `github_url`。步骤 6 一并写入 `analysis.json`。

### 5. 物化源码

物化当前 commit 的完整工作区。获取子模块与 LFS 对象。物化后重新核对。

若来源为本地目录，保留已有修改。

README 中的命令不得单独触发工具安装。

### 6. 写入 `analysis.json`

```bash
mkdir -p "{work_dir}/.sealos"
```

写入 `.sealos/analysis.json`：

```json
{
  "runtime_profile": "local",
  "work_dir": "/path/to/project",
  "repo_name": "my-app",
  "github_url": "https://github.com/owner/repo"
}
```

| 字段 | 说明 |
| --- | --- |
| `runtime_profile` | 与步骤 1 一致：`local` 或 `sandbox` |
| `work_dir` | 可分析、可构建的工作目录绝对路径 |
| `repo_name` | 目录名或 URL 解析结果 |
| `github_url` | 来自参数或 `git remote`；非 GitHub 项目时为 `null` |

Phase 0 结束时文件仅含上述字段。Phase 1 写入 `official_template`。Phase 2 写入 `deployment_plan` 指针。Phase 3 写入 `build_result` 指针（仅在本 Phase 实际运行后）。

### 7. 启动部署日志

创建部署日志。记录 Phase 0 阶段边界与关键决策。后续各阶段继续追加。

## 停止条件

| 结果 | 条件 |
| --- | --- |
| **STOP** | 无法判定 `runtime_profile` |
| **STOP** | 必装依赖无法安装或核对失败 |
| **STOP** | `local`：区域、登录或工作空间未确认 |
| **STOP** | 项目来源无法解析或源码物化失败 |
| **STOP** | 无法写入 `analysis.json` |
| **CONTINUE** | 全部通过 → [部署模式识别](/pipeline/mode-detection) |

## 验收标准

- `runtime_profile` 为 `local` 或 `sandbox`
- 必装依赖已安装且可用
- `local`：Sealos 区域、登录与工作空间已确认
- `.sealos/analysis.json` 存在且包含 `runtime_profile`、`work_dir`、`repo_name`
- `work_dir` 完整、可分析、可构建
