## 目的

Phase 1.5 检查 Sealos 官方模板目录是否已包含本项目。

当且仅有一个模板明确指向同一来源项目，且当前源码无本地修改、自定义分支或其他不可忽略的漂移时，Sealos Deploy：

1. 原样复用官方模板
2. 使用模板定义的镜像、数据库、网络、存储及其他资源
3. 跳过 Phase 2、3、4、5 和 5.5
4. 收集必需模板输入后进入 [Phase 6](/pipeline/phases/phase-6-deploy)

无精确匹配、多个匹配、本地漂移或目录来源未验证时，Agent 继续 [Phase 2](/pipeline/phases/phase-2-discover)。目录暂时不可达不停止部署。

**精确匹配**指模板明确对应同一来源项目。Agent 不得按项目名称、语言或框架模糊匹配。复用官方模板部署的是模板版本，不是当前目录的重建。

<Note>
Phase 5 生成时的相似模板参考**未实现**。当前流程不进行相似度匹配，也不部署近似模板。
</Note>

| 官方模板 | `.sealos/template/index.yaml` | 仅当路径为 `deploy_official_template` |

## 前置条件

- Phase 1 已完成

## 流程

1. 查询官方模板目录，寻找与当前来源项目的精确匹配。
2. 验证无本地漂移使匹配无效。
3. 在 `template-references.json` 中记录匹配元数据与路径。
4. 路径为 `deploy_official_template` 时，将所选 YAML 原样复制到 `.sealos/template/index.yaml`。
5. 标准路径下继续 Phase 2，不得在部分匹配间猜测。

进入 Phase 6 前，官方模板须再次通过在线目录验证。中断恢复后仅凭本地记录不足。

## 停止条件

| 结果 | 条件 |
| --- | --- |
| **CONTINUE → Phase 6** | 唯一精确匹配，路径 `deploy_official_template` |
| **CONTINUE → Phase 2** | 无匹配、模糊匹配、漂移或来源未验证 |

Phase 1.5 除目录访问按标准路径继续处理外，不停止流水线。

## 验收标准

- `template-references.json` 记录路径决策
- 快速路径所选官方 YAML 为原样复制
- 无基于相似度的模板选择
