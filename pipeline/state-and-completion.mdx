## 首次部署何时完成

首次部署仅在**全部**条件为真时完成：

1. Phase 1 入口判断与就绪度评估已完成
2. 线上部署中运行时镜像已确认
3. 模板通过源适配检查与部署预检
4. 用户已提供必填配置并确认部署
5. 云端资源已创建并就绪
6. 运行事实验收对工作负载适用的入口与行为已通过
7. 日志、事件与重启在稳定窗口内已收敛
8. 状态与历史已记录并通过 schema 验证
9. GitHub URL 来源在临时 checkout 清理前已更新桥接 `state.json`

## state.json 内容

Phase 6.5 通过后，Sealos Deploy 保存：

| 字段组 | 内容 |
| --- | --- |
| 身份 | 应用名、适用时的访问 URL |
| 上下文 | Sealos 区域与工作空间 |
| 镜像 | 可识别时的主运行时镜像 |
| 服务 | 每个可更新服务：工作负载、容器、digest、拉取模式、构建定义 |
| 模板 | 使用官方模板时的模板名与目录版本 |
| 历史 | 首次部署时间、最后更新、部署方式、结果、操作日志 |

一次性 Job 是部署事实，但不进入就地 UPDATE 服务映射。

主服务与主镜像仅在存在公网入口或明确应用意图时记录。无公网入口的 worker 可省略 App URL，不阻止成功。

## 持久化规则

1. 写入后运行完整 JSON 产物 schema 验证。
2. GitHub URL 来源将已验证 `state.json` 复制到桥接路径。
3. 验证或持久化失败时不得报告部署成功。
4. 6.5、验证与桥接更新成功前不得删除临时 checkout。

## 最终摘要

展示实际路径、已确认运行时镜像、区域、适用时的 App URL 与日志位置。官方模板路径还展示模板名与目录版本。掩码敏感配置。
