[Phase 0](/pipeline/phases/phase-0-preflight) 通过后，Sealos Deploy 判断本次运行是**首次部署**还是对已有应用的**更新**。

## 模式识别步骤

Agent 必须：

1. 读取先前保存的部署状态。
2. 在目标工作空间确认应用仍在运行。
3. 新格式状态缺失时，尝试发现旧流程创建的应用。
4. 发现已有应用时，向用户展示应用、镜像与访问 URL。
5. 让用户选择更新已有应用或创建新实例。

## DEPLOY 模式

首次部署运行 Phase 1 及主生命周期。见 [流水线总览](/pipeline/overview)。

## UPDATE 模式

更新运行 Phase U1 至 U3。跳过评估、发现、模板生成与完整部署。见 [更新模式](/pipeline/update-mode)。

## 中断恢复

首次部署中断时，Sealos Deploy 识别已完成的评估、官方模板选择、镜像构建或模板生成。

Agent 仅在产物仍与当前项目和当前选择匹配时可恢复。官方模板进入 Phase 6 前须通过在线目录验证。Agent 不得仅凭本地记录和 YAML 信任。

否则从合适的较早阶段重新开始。

## GitHub URL 桥接状态

GitHub URL 部署使用临时 checkout。项目目录中的 `.sealos/state.json` 不能作为清理后下次运行的唯一依据。

对于 GitHub 来源，Sealos Deploy 在以下路径保存稳定的桥接副本：

```
~/.sealos/deployments/github.com/<owner>/<repo>/state.json
```

桥接目录仅包含已验证的 `state.json`。Agent 在新 checkout 上于模式识别前恢复它。仅在 [Phase 6.5](/pipeline/phases/phase-6-5-runtime-truth) 成功且完整状态通过 schema 验证后更新。

构建结果、模板及其他运行本地产物不复制到桥接目录。
