## 目的

部署模式识别确认已有应用后，Phase U1 让用户选择：

| 选择 | 动作 |
| --- | --- |
| 代码已变更 | 重建并推送一个或多个服务 |
| 代码未变更 | 重启一个或多个已有工作负载 |

## 输入

| 输入 | 来源 |
| --- | --- |
| `state.json` | 先前成功部署 |
| 线上应用上下文 | 部署模式识别 |
| 用户选择 | 重建目标或重启目标 |

## 输出

| 输出 | 说明 |
| --- | --- |
| 重建计划 | 逐服务 context、Dockerfile、target、arg 名称 |
| 新 digest | 重建时按 Phase 3 规则 |
| 重启计划 | 无镜像变更时要滚动的工作负载 |

## 流程

**重建路径：** 每个服务保留构建目录、Dockerfile、target 与 arg 名称。使用 `linux/amd64`，推送到 GHCR，从 Buildx 元数据读取 digest。所有选定重建成功后才启动云端变更。

**重启路径：** 每个服务保持当前 digest。

## 停止条件

| 结果 | 条件 |
| --- | --- |
| **STOP** | 重建失败，或全应用 GHCR namespace 冲突 |
| **CONTINUE → Phase U2** | 计划完成 |

## 验收标准

- 用户选择已记录
- 重建时所有选定重建在 U2 前成功
