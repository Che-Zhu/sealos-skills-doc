## 来源类型

| 来源 | 检测 | 所需工具 |
| --- | --- | --- |
| 官方模板 | Phase 1 与 [`kb-0.9/template`](https://github.com/labring-actions/templates/tree/kb-0.9/template) 精确匹配 | 无（快速路径） |
| Docker Compose | `docker-compose.yml` / `compose.yaml` | kompose |
| Helm | `Chart.yaml` 或 chart 目录 | Helm 3+ |
| Kubernetes | 原生清单 | Python/PyYAML |
| 隐式 | 无显式拓扑文件 | 项目结构分析 |

## 来源选择优先级

Phase 2 按拓扑证据顺序选择部署源。Compose、Helm 与 Kubernetes 显式文件优先于隐式路径。多个显式来源冲突时，Agent 须从项目证据（README、CI、文档）确定主拓扑，不得猜测。

## 条件性源码物化

Git LFS、子模块等机制仅在仓库声明时安装与获取。见 [Phase 0](/pipeline/phases/phase-0-preflight)。

## 拓扑保留

完整 `service_inventory` 须保留数据库、队列、缓存与 worker。仅构建的服务与最终运行时拓扑分开处理。Phase 5 不得因非主应用服务而丢弃依赖。
