`deployment-plan.json` 由 [Phase 2](/pipeline/phases/phase-2-discover) Subagent 写入 `.sealos/phase-2/deployment-plan.json`。

## 目的

Phase 2 完成侦察与**镜像准备**后，在计划中声明**唯一部署源路径** `deployment_source`。下游 Phase 3、4 只读该指针，不再维护平行组件清单。

一次 Sealos 部署对应整仓一张模板。拓扑须覆盖全部相关组件（含数据库、队列、worker），不得只写主应用。

Subagent 不构建、不推送镜像，不生成 Sealos 模板。`analysis.json` 仅通过 `deployment_plan` 指向本文件，不在 `analysis.json` 重复写入 `deployment_source`。

## 文件位置

```
.sealos/phase-2/deployment-plan.json
.sealos/phase-2/docker-compose.yml          # 非 Helm/K8s 时由 Phase 2 写入（canonical）
```

须落盘的 Dockerfile 路径由部署源中的 `build.dockerfile`（或等价字段）声明，不单独规定目录结构。

## 顶层字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `generated_at` | string (date-time) | 否 | 写入时间 |
| `deployment_source` | string | 是 | 部署源路径，相对 `work_dir`（见下表） |

## `deployment_source` 取值

Phase 2 按 [部署源选择](/pipeline/deployment-sources) 优先级（Helm → Kubernetes → Compose）选定**一条**路径：

| 情况 | `deployment_source` 指向 | Phase 2 额外动作 |
| --- | --- | --- |
| **Helm** | chart 根目录（含 `Chart.yaml`），如 `./charts/myapp` | 检查 chart；须构建的镜像补齐 Dockerfile；**不**生成 compose |
| **Kubernetes** | **单个** manifest 文件，如 `k8s/deployment.yaml` | 检查清单；须构建的镜像补齐 Dockerfile；**不**生成 compose |
| **其它**（含已有 compose、单应用、隐式拓扑） | **固定** `.sealos/phase-2/docker-compose.yml` | 从仓库 compose 复制/修补，或生成 compose；补齐 `build` 与 Dockerfile |

规则：

- Compose 路径**始终**指向 `.sealos/phase-2/docker-compose.yml`，不得直接指向仓库内 `docker-compose.yml`。
- Helm 与 Kubernetes 同时存在时，按 Helm → Kubernetes 优先级；仍冲突则从 README、CI、文档定案。
- 须落盘的 Dockerfile 优先写在 `.sealos/phase-2/` 下，路径与部署源中的 `build.dockerfile` 一致；不得修改用户仓库源码（Helm values、K8s manifest、compose 的 canonical 副本除外）。

## 镜像准备

无论 `deployment_source` 类型，Phase 2 均须确保：凡须从本仓库构建的容器，在 Phase 2 结束时已有可构建的 Dockerfile，并在部署源中引用正确路径。

1. 仓库内已有可用 Dockerfile（含 Compose `build.dockerfile`）→ 直接复用。
2. 无可用 Dockerfile → 运行 `railpack`（`info`、`plan`），**直接阅读输出**，审核后按需补全（端口、启动命令、多阶段构建、环境变量等），再写入部署源所引用的 dockerfile 路径。

有明确上游镜像引用的组件不生成 Dockerfile。不得从组织名或仓库名猜测镜像。

## 示例

**Helm：**

```json
{
  "generated_at": "2026-08-02T12:00:00Z",
  "deployment_source": "./charts/myapp"
}
```

**Kubernetes：**

```json
{
  "deployment_source": "deploy/app.yaml"
}
```

**Compose（含仓库已有 compose 或隐式拓扑）：**

```json
{
  "deployment_source": ".sealos/phase-2/docker-compose.yml"
}
```

## JSON Schema

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "https://skills.sh/sealos-deploy/schemas/deployment-plan.schema.json",
  "title": "Sealos Deploy Deployment Plan",
  "type": "object",
  "additionalProperties": false,
  "required": ["deployment_source"],
  "properties": {
    "generated_at": { "type": "string", "format": "date-time" },
    "deployment_source": { "type": "string", "minLength": 1 }
  }
}
```

## 下游用法

| 阶段 | 读取方式 |
| --- | --- |
| Phase 2（主 Agent） | 在 `analysis.json` 写入 `deployment_plan` 指针 |
| Phase 3 | 顺序构建并推送；写入 `build-result.json`（`pushed`、`pull_access`）与 `analysis.json` 的 `build_result` 指针 |
| Phase 4 | 读取 `deployment_source`，按路径类型选择适配器（compose / helm / kubernetes） |

## 验收

- `deployment_source` 存在且为 `work_dir` 内有效相对路径
- Helm/K8s 路径指向真实 chart 或 manifest 文件
- 非 Helm/K8s 时 `deployment_source` 为 `.sealos/phase-2/docker-compose.yml`，且该文件存在并覆盖完整拓扑
- 须构建的组件在 Phase 2 结束时已有 Dockerfile
- 文件通过上述 JSON Schema
