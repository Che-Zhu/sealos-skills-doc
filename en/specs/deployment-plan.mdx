The Phase 2 [subagent](/en/pipeline/phases/phase-2-discover) writes `deployment-plan.json` to `.sealos/phase-2/deployment-plan.json`.

## Purpose

After scout and **image preparation**, Phase 2 declares a single deployment source path in `deployment_source`. Downstream Phase 3 and 4 read only this pointer — no parallel component list.

One Sealos deploy maps to one full-repo template. Topology must cover all relevant components (databases, queues, workers), not only the main app.

The subagent does not build, push, or produce Sealos templates. `analysis.json` points to this file via `deployment_plan` only; do not duplicate `deployment_source` in `analysis.json`.

## File location

```
.sealos/phase-2/deployment-plan.json
.sealos/phase-2/docker-compose.yml          # written by Phase 2 when not Helm/K8s (canonical)
```

Dockerfile paths on disk are declared by `build.dockerfile` (or equivalent) in the deployment source — no fixed subdirectory layout.

## Top-level fields

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `generated_at` | string (date-time) | No | Write timestamp |
| `deployment_source` | string | Yes | Deployment source path, relative to `work_dir` (see table below) |

## `deployment_source` values

Phase 2 picks **one** path per [deployment source selection](/en/pipeline/deployment-sources) priority (Helm → Kubernetes → Compose):

| Case | `deployment_source` points to | Extra Phase 2 work |
| --- | --- | --- |
| **Helm** | Chart root (contains `Chart.yaml`), e.g. `./charts/myapp` | Check chart; prepare Dockerfiles for images that need build; **do not** generate compose |
| **Kubernetes** | **Single** manifest file, e.g. `k8s/deployment.yaml` | Check manifests; prepare Dockerfiles for images that need build; **do not** generate compose |
| **Other** (existing compose, single app, implicit topology) | **Fixed** `.sealos/phase-2/docker-compose.yml` | Copy/patch from repo compose or generate compose; add `build` and Dockerfiles |

Rules:

- Compose path is **always** `.sealos/phase-2/docker-compose.yml` — never the repo's `docker-compose.yml` directly.
- When Helm and Kubernetes both exist, use Helm → Kubernetes priority; if still ambiguous, resolve from README, CI, or docs.
- New Dockerfiles on disk prefer `.sealos/phase-2/` at the path referenced by `build.dockerfile`; do not modify user source (except canonical compose copy, Helm values, or K8s manifest patches as needed).

## Image preparation

Regardless of `deployment_source` type, Phase 2 must ensure every container built from this repo has a buildable Dockerfile by phase end, referenced correctly in the deployment source.

1. Reuse an existing Dockerfile in the repo when usable (including Compose `build.dockerfile`).
2. When none exists: run `railpack` (`info`, `plan`), **read the output directly**, review and refine (ports, start command, multi-stage build, env vars), then write to the dockerfile path referenced in the deployment source.

Skip Dockerfile generation for components with a known upstream image. Do not guess images from org or repo name.

## Examples

**Helm:**

```json
{
  "generated_at": "2026-08-02T12:00:00Z",
  "deployment_source": "./charts/myapp"
}
```

**Kubernetes:**

```json
{
  "deployment_source": "deploy/app.yaml"
}
```

**Compose (repo compose or implicit topology):**

```json
{
  "deployment_source": ".sealos/phase-2/docker-compose.yml"
}
```

## JSON Schema

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "https://skills.sh/sealos-deploy/schemas/deployment-plan.schema.json",
  "title": "Sealos Deploy Deployment Plan",
  "type": "object",
  "additionalProperties": false,
  "required": ["deployment_source"],
  "properties": {
    "generated_at": { "type": "string", "format": "date-time" },
    "deployment_source": { "type": "string", "minLength": 1 }
  }
}
```

## Downstream usage

| Phase | How it reads the file |
| --- | --- |
| Phase 2 (main agent) | Writes `deployment_plan` pointer in `analysis.json` |
| Phase 3 | Sequential build and push; writes `build-result.json` (`pushed`, `pull_access`) and `build_result` pointer in `analysis.json` |
| Phase 4 | Reads `deployment_source`; selects adapter by path type (compose / helm / kubernetes) |

## Acceptance

- `deployment_source` exists and is a valid relative path under `work_dir`
- Helm/K8s paths point to a real chart or manifest file
- When not Helm/K8s, `deployment_source` is `.sealos/phase-2/docker-compose.yml` and that file exists with full topology
- Every build-required component has a Dockerfile after Phase 2
- File passes the JSON Schema above
