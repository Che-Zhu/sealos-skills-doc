Each deploy phase has two sections:

| Section | When | Content |
| --- | --- | --- |
| **Phase constraints** | Read when **entering** this phase; obey **while executing** | Unique facts, platform quirks, scope boundaries. Artifacts often **do not exist yet** |
| **Phase validation** | **Before exit** from this phase | `validate-phase-N.mjs` checks **outputs** against the contract |

Constraints use IDs (for example `P3-01`). Checkable constraints fail under the same ID in the script. Behavior-only rules that scripts cannot see stay in phase constraints only, not in the validation table.

Implementation lives in [`sealos-skills`](https://github.com/labring/sealos-skills): `skills/sealos-deploy/scripts/validate-phase-N.mjs` (`N` = 0–7).

## How to run

```bash
node skills/sealos-deploy/scripts/validate-phase-0.mjs --dir "$WORK_DIR"
# … validate-phase-1.mjs … validate-phase-7.mjs
```

`$WORK_DIR` is `work_dir` from `analysis.json`.

## Relation to schema validation

| Layer | Command | Scope |
| --- | --- | --- |
| Global artifact schemas | `validate-artifacts.mjs` | Structurally valid JSON/YAML |
| Phase validation | `validate-phase-N.mjs` | **Semantic** rules for that phase (platform quirks, cross-artifact consistency) |
| Phase 4 deploy gate | `check_consistency.py` | Template rule subset (`validate-phase-4.mjs` invokes or equivalent) |

Phase validation does **not** replace schema validation. Run both before exit when applicable.

## Skip rules

| Phase | When to skip validation |
| --- | --- |
| Phase 3 | No build required; `build_result` not written |
| Phase 1, 2 | UPDATE mode skips these phases |
| Others | If you enter the phase, you must validate |
