All pipeline outputs are written under `.sealos/` in the target project directory.

```
{WORK_DIR}/.sealos/
├── config.json
├── state.json
├── analysis.json
├── phase-2/
│   ├── gitingest-digest.txt
│   ├── deployment-plan.json
│   └── docker-compose.yml
├── phase-3/
│   └── build-result.json
├── phase-4/
│   ├── image-digests.json
│   ├── source/
│   ├── rendered.yaml
│   └── resource-map.json
└── template/
    └── index.yaml
```

## Main artifacts

| File | Written in | Read in | Description |
| --- | --- | --- | --- |
| `analysis.json` | Phase 0, Phases 1–2 | Phase 3–4 | Phase 2 adds `deployment_plan`; Phase 3 adds `build_result` (only after Phase 3 runs) |
| `phase-2/deployment-plan.json` | Phase 2 | Phase 3, 4 | Contains `deployment_source` pointer |
| `phase-2/gitingest-digest.txt` | Phase 2 | Phase 2 | gitingest scout input |
| `phase-2/docker-compose.yml` | Phase 2 | Phase 3, 4 | Canonical compose (when not Helm/K8s) |
| `template/index.yaml` | Phase 1 (official exact match) or Phase 4 (standard path) | Phase 5, 6 | Canonical deploy template |
| `phase-3/build-result.json` | Phase 3 | Phase 4 | Tag refs (`pushed`) and `pull_access` for pushed images |
| `phase-4/image-digests.json` | Phase 4 | Phase 4 | All container images as `repository@sha256:...` (`linux/amd64`) |
| `phase-4/` | Phase 4 | — | Conversion intermediates (`source/`, `rendered.yaml`, `resource-map.json`) |
| `state.json` | After Phase 7 | Deploy mode detection, UPDATE | Deploy state and service mapping |
| `config.json` | User or Phase 5 | Phase 5 | User config overrides |

Field contracts: [deployment-plan.json](/en/specs/deployment-plan). Other JSON artifacts: [Artifact schemas](/en/specs/artifact-schemas).
