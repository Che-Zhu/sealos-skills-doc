## Source types

| Source | Detection | Required tools |
| --- | --- | --- |
| Official template | Phase 1 exact catalog match (fast path) | None (fast path) |
| Docker Compose | `docker-compose.yml` / `compose.yaml` | kompose |
| Helm | `Chart.yaml` or chart directory | Helm 3+ |
| Kubernetes | Native manifests | Python/PyYAML |
| Implicit | No explicit topology file | Project structure analysis |

## Source selection precedence

Phase 4 selects the deployment source from `deployment-plan.json`, `gitingest-digest`, and the rules below. Explicit Compose, Helm, and Kubernetes files take precedence over implicit paths. When multiple explicit sources conflict, resolve the primary topology from README, CI, or docs — do not guess. One Sealos deploy must cover every component in `deployment-plan.json`.

## Topology preservation

`deployment-plan.json` `items` must include databases, queues, caches, and workers. Build-only components are handled separately from final runtime topology. Phase 4 must not drop dependencies because they are not the main app.
