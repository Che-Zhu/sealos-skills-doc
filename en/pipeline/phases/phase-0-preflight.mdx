## Purpose

Decide the runtime profile, install required dependencies, prepare identity, and enter an analyzable source directory. Write `runtime_profile`, `work_dir`, `repo_name`, and `github_url` to `.sealos/analysis.json`.

Do not judge deployability. Do not build images. Do not generate templates. Do not create cloud resources.

## Inputs

| Input | Source |
| --- | --- |
| `SEALAI_DEPLOY_TASK_ID` | Process environment |
| Host environment | OS and package managers |
| Project source | Skill argument: GitHub URL, local path, or `$(pwd)` when omitted |

## Outputs

| Output | Description |
| --- | --- |
| `.sealos/analysis.json` | Only `runtime_profile`, `work_dir`, `repo_name`, `github_url` (overwrite) |
| Sealos context (`local` only) | Region, workspace, auth, kubeconfig |
| Deploy log | `~/.sealos/logs/deploy-*.log` |
| Result | `CONTINUE` or `STOP` |

## Preconditions

None.

## Phase constraints

Read when entering this phase. Obey **while executing**.

| ID | Constraint | Notes |
| --- | --- | --- |
| P0-01 | Do not judge deployability | Deployability is Phase 1 |
| P0-02 | Do not build images, generate templates, or create cloud resources | Environment, identity, and source prep only |
| P0-03 | If `SEALAI_DEPLOY_TASK_ID` exists, write `sandbox`; else write `local` | See procedure step 1 |
| P0-04 | List missing deps once, ask once, then install; refuse or failure → STOP | See procedure step 2 |
| P0-05 | Probe scripts detect only; they never install | `check-running-environment.mjs` |
| P0-06 | Do not require global `sealos-cli` or `agentlens` binaries; use `npx` when needed | Identity and Phase 2 scout |
| P0-07 | Git LFS and submodules are on demand, not default required installs | See procedure step 5 |
| P0-08 | `gh` login / `write:packages` are warnings in this phase | Hard block only when a later phase chooses GHCR push |

## Phase validation

Run **after outputs are written**:

```bash
node skills/sealos-deploy/scripts/validate-phase-0.mjs --dir "$WORK_DIR"
```

| ID | Check |
| --- | --- |
| P0-V01 | `.sealos/analysis.json` exists with only the four Phase 0 fields |
| P0-V02 | `runtime_profile` matches the `SEALAI_DEPLOY_TASK_ID` rule |
| P0-V03 | `work_dir` is an existing absolute path |

On failure, do not enter [Mode detection](/en/pipeline/mode-detection).

## Procedure

### 1. Probe environment and dependencies

Run `skills/sealos-deploy/scripts/phase-0/check-running-environment.mjs`.

The script detects only:

1. `runtime_profile` from `SEALAI_DEPLOY_TASK_ID`
2. Present tools, missing tools, and warnings

**`local` and `sandbox`:**

git, Node.js 18+, Python 3.8+, PyYAML, kompose, Helm 3+, kubectl, curl, jq

**`local` only:**

`gh` (binary), Docker CLI, running Docker daemon, Docker Buildx, [railpack](https://github.com/railwayapp/railpack)

`sandbox` includes railpack and does not require Docker or `gh`.

**Not required installs (`npx`):** `sealos-cli`; `@norberia/agentlens` (Phase 2 scout). Do not install or depend on gitingest.

**Warnings (not STOP here):** incomplete `gh` login or missing `write:packages`. Enforce them only when the run later chooses GHCR push.

### 2. Install missing dependencies

If anything is missing: list once, ask once, install on agreement, re-run the probe. Refuse or remaining gaps → `STOP`.

If Docker is installed but the daemon is stopped, ask, then start it.

### 3. Prepare identity (`local` only)

Skip in `sandbox`.

Use `sealos-cli` (or `npx -y sealos-cli@latest`):

1. Select region from skill `config.json`
2. Login
3. Select workspace
4. Confirm `~/.sealos/` auth and kubeconfig are usable without printing them

### 4. Enter the source directory

| Source | Action |
| --- | --- |
| GitHub repository URL | Shallow clone (`--depth 1`) |
| Local project directory | Use that path |
| No argument | Use `$(pwd)` |

Always shallow-clone. Never fetch full history:

```bash
git clone --depth 1 "<github-url>" "$WORK_DIR"
```

Resolve `repo_name` and `github_url` (`null` when not GitHub).

### 5. Optional submodules and Git LFS

Only when the repo declares them. Ask once. Refuse or failure → `STOP`. Do not install tools only because a README mentions a command.

### 6. Write `analysis.json`

Overwrite `.sealos/analysis.json` with only:

```json
{
  "runtime_profile": "local",
  "work_dir": "/path/to/project",
  "repo_name": "my-app",
  "github_url": "https://github.com/owner/repo"
}
```

Phase 1 later writes the full analysis snapshot and keeps `runtime_profile`. Resume must not treat a Phase 0-only file as Phase 1 complete.

### 7. Start the deploy log

Create `~/.sealos/logs/deploy-<YYYYMMDD-HHmmss>.log` and record Phase 0 boundaries.

## Stop conditions

| Result | Condition |
| --- | --- |
| **STOP** | `runtime_profile` cannot be determined |
| **STOP** | Required dependency install refused or still failing |
| **STOP** | `local`: region, login, or workspace not confirmed |
| **STOP** | Project source cannot be resolved or entered |
| **STOP** | Required submodules/LFS refused or fetch failed |
| **STOP** | `analysis.json` write or `validate-phase-0.mjs` fails |
| **CONTINUE** | All checks pass → [mode detection](/en/pipeline/mode-detection) |

## Acceptance

- `runtime_profile` is `local` or `sandbox`
- Required dependencies are installed
- `local`: Sealos region, login, and workspace confirmed
- `.sealos/analysis.json` contains only the four Phase 0 fields
- `work_dir` is analyzable
