## Purpose

Phase 4 belongs to the standard build path only. It reads `deployment-plan.json` to decide whether images must be built first, then generates the full Sealos template per [Deployment sources](/en/pipeline/deployment-sources) rules.

The current implementation does not read similar templates or catalog YAML. The template must follow current project facts and conversion rules.

## Entry branch

Read `deployment_plan` and `items` in `deployment-plan.json`:

| Case | Action |
| --- | --- |
| Every `item` has `image` and digest is resolved | Skip Phase 3; continue template generation in this phase |
| One or more items lack `image`, or digest is not ready | **CONTINUE → Phase 3**; return to this phase after Phase 3 completes |

## Inputs

| Input | Source |
| --- | --- |
| `analysis.json` | Phases 0–2 |
| `deployment-plan.json` | Phase 2 (via `analysis.json` → `deployment_plan`) |
| Build results | Phase 3 (if this phase entry branch entered Phase 3) |
| Deployment source files | `.sealos/deployment-source/` (generated in Phase 4 when needed) |

## Outputs

| Output | Path | Description |
| --- | --- | --- |
| Canonical template | `.sealos/template/index.yaml` | Single template for 4.5, 5, and recovery |
| Resource map | `.sealos/deployment-source/resource-map.json` | Source to output accounting |
| Topology evidence | `.sealos/topology-evidence/{app-name}.yaml` | Validator-only |

## Conversion paths

| Source kind | Method |
| --- | --- |
| Compose | Deterministic converter with `--dry-run`; per-service image overrides for Phase 3 digests |
| Helm | `helm template` on chart copy; adapter preserves rendered resources |
| Kubernetes | Source adapter preserves resources and converts unsupported fields |
| Implicit | AI constructs temporary Compose input from confirmed services and digests |

Adapters are preferred tools, not eligibility gates. When an adapter cannot express the project, the agent may fix temporary input or generate an equivalent canonical template. The agent must pass the same quality gate without dropping services or bypassing validation.

## Network and ports

- `ports` → public ingress candidate
- `expose` → internal Service only
- One public candidate auto-selected; multiple candidates resolved from Ingress, README, roles, or `.sealos/config.json` `public_service`
- Internal service refs rewrite to Kubernetes Service FQDN

## Images and pull secrets

Final container images must be `repository@sha256:...`. Pull-secret refs apply only when Phase 3 reports `ghcr_secret_required` or `indeterminate` for that service key.

## Databases

Priority:

1. External database declared → keep external connection
2. Supported service DB without external intent → KubeBlocks default
3. Embedded SQLite → keep inside app
4. Unsupported or non-lossless KubeBlocks conversion → preserve source workload with `docker-to-sealos.kubeblocks-fallback-reason`

## Resource floors

Hard minimums per component role (business main, sidecar/init/job, KubeBlocks component). AI may raise limits from project evidence. Quality gate enforces floors and valid Sealos resource steps.

## Stop conditions

| Result | Condition |
| --- | --- |
| **STOP** | Quality gate fails on `index.yaml` |
| **CONTINUE → Phase 4.5** | Template passes full quality gate |

Regenerate and re-run the full gate before continuing. Partial fixes are not allowed.

## Acceptance

- `.sealos/template/index.yaml` exists
- All final images are digest-pinned
- Full topology preserved in resource map
- Quality gate pass recorded
