## Purpose

Phase 4 belongs to the standard build path. It reads `deployment_source` from `deployment-plan.json` and writes `.sealos/template/index.yaml`.

The [Phase 1](/en/pipeline/phases/phase-1-assess) official-template fast path skips this phase.

Do not create cloud resources. Do not push images. Do not modify `deployment_source` (invalid source → **RETURN → Phase 2**).

## Prerequisites

- Phase 2 wrote `deployment_plan` and `deployment-plan.json`
- `deployment_source` is readable (see [Deployment sources](/en/pipeline/deployment-sources))

## Inputs

| File | Notes |
| --- | --- |
| `.sealos/analysis.json` | Pointer entry |
| `.sealos/phase-2/deployment-plan.json` | Contains `deployment_source` |
| `.sealos/phase-3/build-result.json` | When builds ran |

## Outputs

| Output | Path |
| --- | --- |
| Sealos template | `.sealos/template/index.yaml` |

Phase 5 reads only the row above. The rest live under `.sealos/phase-4/` and are **not** Sealos templates:

| Intermediate | Path | Role |
| --- | --- | --- |
| Source snapshot | `.sealos/phase-4/source/` | Convertible copy of the deployment source |
| Helm render | `.sealos/phase-4/rendered.yaml` | Helm path: `helm template` output |
| Resource map | `.sealos/phase-4/resource-map.json` | Source workload to template resource accounting |

## Flow

### 1. Entry and resume

- If `.sealos/template/index.yaml` exists → follow [resume rules](/en/pipeline/mode-detection#interrupt-recovery).
- Otherwise continue at step 2.

### 2. Prepare intermediates

Leave a convertible snapshot under `.sealos/phase-4/source/`. Do not re-scout the repo.

| Source type | Action |
| --- | --- |
| Compose | Copy `deployment_source` to `source/` |
| Helm | Copy chart to `source/`; `helm template` → `.sealos/phase-4/rendered.yaml` |
| Kubernetes | Copy manifest to `source/` |

After this step, if builds are required and `build_result` is not ready → **CONTINUE → Phase 3** (on return, continue at step 3).

### 3. Pin digests and convert

Each container image must be `repository@sha256:...` (`linux/amd64`). Workload keys match the deployment source.

| Image source | Action |
| --- | --- |
| Built in-repo | `build-result.json` → `digests` |
| Upstream `image:` | Agent resolves tag; do not write `build-result.json` |

Convert by `deployment_source` type. Apply digest overrides before or via conversion parameters:

| Type | Conversion |
| --- | --- |
| Compose | `compose_to_template.py` (default `--kompose-mode always`; runs `kompose convert` for workload shapes); per-service `--image-override` |
| Helm | Read `rendered.yaml` → adapter; replace `image` by key |
| Kubernetes | Adapter; replace `image` by workload name |

Do not drop services. Write `.sealos/phase-4/resource-map.json` and `.sealos/template/index.yaml`.

### 4. Deploy gate

Run the [deploy gate](/en/specs/template-format#deploy-gate) on `.sealos/template/index.yaml` (`check_consistency.py` rule subset). Do **not** run the full `quality_gate.py` CI bundle. On failure → **STOP**. Regenerate and rerun the full gate after fixes.

### 5. Downstream

On pass → **CONTINUE → [Phase 4.5](/en/pipeline/phases/phase-4-5-configure)** → [Phase 4.9](/en/pipeline/overview#first-deploy-routes) → Phase 5.

## Conversion constraints

**Network:** `ports` is a public candidate; `expose` is internal Service only. With multiple candidates, resolve from Ingress, README, role, or `public_service` in `.sealos/config.json`. Rewrite internal refs to Service FQDN.

**Pull secret:** Add pull-secret refs only when `pull_access` for that key in `build-result.json` is `ghcr_secret_required`.

**Databases:** External declaration → keep external; supported service DB → KubeBlocks; SQLite → keep in app; otherwise keep source workload with `docker-to-sealos.kubeblocks-fallback-reason`.

**Resource floors:** See [Resource floors](/en/specs/resource-floors) and the [deploy gate](/en/specs/template-format#deploy-gate).

## Stop conditions

| Result | Condition |
| --- | --- |
| **CONTINUE → Phase 3** | Build required and digests not ready |
| **CONTINUE → Phase 4.5** | Deploy gate passed |
| **RETURN → Phase 2** | Invalid deployment source (missing Dockerfile, bad context, incomplete topology) |
| **STOP** | Conversion failed, digest resolution failed, or deploy gate failed |

## Acceptance

- `.sealos/template/index.yaml` exists and passed the deploy gate
- All images are digest-pinned (`linux/amd64`)
- `.sealos/phase-4/resource-map.json` has full topology
