## Purpose

Phase 2 uses a subagent to produce `deployment-plan.json` with a single **`deployment_source` pointer** for downstream conversion, and to **prepare images** for components that need build (reuse repo Dockerfiles, or produce and review a build recipe via railpack).

One Sealos deploy maps to **one full-repo template**. Topology must cover all relevant components (including databases, queues, and workers), not only the main app.

Do not build or push images in this phase. Do not generate a Sealos template. Do not create cloud resources. Do not modify `official_template`.

UPDATE mode skips this phase.

| Input | Source |
| --- | --- |
| `analysis.json` | Phase 0, Phase 1 |
| Project source and docs | `analysis.json` → `work_dir` |
| `railpack` | Installed in Phase 0 (`sandbox` preinstalled; `local` must be available) |
| `gitingest` | Installed in Phase 0 |

## Outputs

| Output | Path | Description |
| --- | --- | --- |
| Deployment digest | `.sealos/phase-2/gitingest-digest.txt` | gitingest output (scope in step 2) |
| Deployment plan | `.sealos/phase-2/deployment-plan.json` | Contains `deployment_source` |
| Canonical Compose | `.sealos/phase-2/docker-compose.yml` | Only on non-Helm/K8s path |
| `analysis.json` | `.sealos/analysis.json` | Adds `deployment_plan` pointer |

See [deployment-plan.json](/en/specs/deployment-plan) for the field contract.

## Procedure

### 1. Read `analysis.json`

Read `work_dir`, `runtime_profile`, and related fields. Preserve Phase 0 and Phase 1 fields. Do not modify `official_template`.

### 2. Main agent scout

Read root `README*`, `CONTRIBUTING*`, and similar docs. Run `gitingest` in `work_dir` for deploy and CI evidence. Do not ingest the full repository source. Write output to `.sealos/phase-2/gitingest-digest.txt`.

Include file types such as:

- `README*`, `CONTRIBUTING*`
- `docker-compose*`, `compose.y*ml`, `Dockerfile*`
- `Chart.yaml`, Helm `values*.yaml`, `**/templates/**`
- `**/k8s/**`, `**/deploy/**`, Kubernetes manifests
- `Makefile`, `Procfile`, `fly.toml`, `render.yaml`, and other PaaS or scripted deploy config
- `package.json`, `pnpm-workspace.yaml`, `turbo.json`, `nx.json`, `go.work`, `Cargo.toml`, `pyproject.toml`, and other workspace clues
- `.github/workflows/**` and other CI config

Record README understanding and scout notes in the deploy log (natural language, a few sentences).

### 3. Subagent — pick deployment source and image prep

The main agent starts one subagent with:

- `analysis.json`
- Path to `.sealos/phase-2/gitingest-digest.txt`
- Verbal handoff from the main agent (findings and judgment, natural language)

Tell the subagent to write `.sealos/phase-2/deployment-plan.json` per [deployment-plan.json](/en/specs/deployment-plan):

1. **Set `deployment_source`** (priority Helm → Kubernetes → Compose):
   - **Helm**: point to chart root; check chart and values; prepare Dockerfiles for images that need build.
   - **Kubernetes**: point to a **single** manifest file; check manifests; prepare Dockerfiles for images that need build.
   - **Other**: generate or normalize compose to `.sealos/phase-2/docker-compose.yml` (copy and patch when repo has compose — do not edit the original); `deployment_source` is **fixed** to `.sealos/phase-2/docker-compose.yml`.
2. **Image prep**: every container built from this repo must have a buildable `build` config (context, dockerfile) in the deployment source. When no usable Dockerfile exists in the repo, follow **read railpack output → review → refine** (below).
3. Write Dockerfiles to disk only at paths referenced by the deployment source; prefer `.sealos/phase-2/`; do not modify user source.

The main agent must tell the subagent: **when a Dockerfile is needed, run `railpack` (`info`, `plan`) and read the output directly, review and refine (ports, start command, build stages, etc.), then write to the dockerfile path referenced in the deployment source.**

The subagent decides how to explore. Do not guess published images from org or repo name.

### 4. Write `analysis.json`

Merge with existing Phase 0 and Phase 1 fields. Add only the `deployment_plan` pointer:

```json
{
  "deployment_plan": ".sealos/phase-2/deployment-plan.json"
}
```

Do not modify fields written in Phase 0 or Phase 1 (including `official_template`).

`deployment-plan.json` must pass the [deployment-plan.json contract](/en/specs/deployment-plan). Persist merged `analysis.json` after [artifact schemas](/en/specs/artifact-schemas) validation.

## Stop conditions

| Result | Condition |
| --- | --- |
| **STOP** | Cannot determine `deployment_source` or deployment source is incomplete |
| **STOP** | A build-required component cannot get a Dockerfile |
| **STOP** | `deployment-plan.json` fails schema, or `analysis.json` cannot be written or pass schema |
| **CONTINUE → Phase 4** | Plan, file at `deployment_source`, and `analysis.json` are persisted |

On Phase 3 build failure, return to Phase 2 step 3 to revise the deployment source or Dockerfiles.

## Acceptance

- `deployment-plan.json` has a valid `deployment_source`
- When not Helm/K8s, `.sealos/phase-2/docker-compose.yml` exists with full topology
- Every build-required component has a buildable Dockerfile
- `analysis.json` includes `deployment_plan` with correct path
- `analysis.json` passes schema
