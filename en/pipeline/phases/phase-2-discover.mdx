## Purpose

Phase 2 uses a subagent to produce `deployment-plan.json`, **listing every deployable component required for one Sealos deploy of this repository** (directory + known image when applicable).

One Sealos deploy maps to **one full-repo template**. The list must cover all relevant components (including databases, queues, and workers), not only the main app.

Do not build or push images in this phase. Do not generate a Sealos template. Do not create cloud resources. Do not select a deployment source from `official_template` or modify the `official_template` field.

UPDATE mode skips this phase.

## Inputs

| Input | Source |
| --- | --- |
| `analysis.json` | Phase 0, Phase 1 |
| Project source and docs | `analysis.json` → `work_dir` |
| `railpack` | Installed in Phase 0 (`sandbox` preinstalled; `local` must be available) |
| `gitingest` | Installed in Phase 0 |

## Outputs

| Output | Path | Description |
| --- | --- | --- |
| Deployment digest | `.sealos/phase-2/gitingest-digest.txt` | gitingest output (scope in step 2) |
| Deployment plan | `.sealos/phase-2/deployment-plan.json` | Subagent output; deployable component list |
| `analysis.json` | `.sealos/analysis.json` | Includes `deployment_plan` path; derived fields for Phases 3–4 |

See [deployment-plan.json](/en/specs/deployment-plan) for the field contract.

Deployment source kinds: [Deployment sources](/en/pipeline/deployment-sources).

## Preconditions

- Phase 1 exit is **CONTINUE → Phase 2** (standard path)

## Procedure

### 1. Read `analysis.json`

Read `work_dir`, `runtime_profile`, and related fields. Preserve Phase 0 and Phase 1 fields. Do not modify `official_template`.

### 2. Main agent scout

Read root `README*`, `CONTRIBUTING*`, and similar docs. Run `gitingest` in `work_dir` for deploy and CI evidence. Do not ingest the full repository source. Write output to `.sealos/phase-2/gitingest-digest.txt`.

Include file types such as:

- `README*`, `CONTRIBUTING*`
- `docker-compose*`, `compose.y*ml`, `Dockerfile*`
- `Chart.yaml`, Helm `values*.yaml`, `**/templates/**`
- `**/k8s/**`, `**/deploy/**`, Kubernetes manifests
- `Makefile`, `Procfile`, `fly.toml`, `render.yaml`, and other PaaS or scripted deploy config
- `package.json`, `pnpm-workspace.yaml`, `turbo.json`, `nx.json`, `go.work`, `Cargo.toml`, `pyproject.toml`, and other workspace clues
- `.github/workflows/**` and other CI config

Record README understanding and scout notes in the deploy log (natural language, a few sentences).

### 3. Subagent — deployable component list

The main agent starts one subagent with:

- `analysis.json`
- Path to `.sealos/phase-2/gitingest-digest.txt`
- Verbal handoff from the main agent (findings and judgment, natural language)

Tell the subagent: **list every component required for one Sealos deploy of this repository**; give each item a directory `path` and an `image` when known; explore the repository; `railpack` is available (`info`, `plan`); write output to `.sealos/phase-2/deployment-plan.json`.

The subagent decides how to explore and whether to run railpack. Do not guess published images from org or repo name.

### 4. Write `analysis.json`

```json
{
  "deployment_plan": ".sealos/phase-2/deployment-plan.json"
}
```

Merge with existing Phase 0 and Phase 1 fields. Supplement Phases 3–4 fields from `items` in `deployment-plan.json` (such as `deployment_source`, `service_inventory`, `image_inventory`). Use `null`, `[]`, or `{}` for unknowns. Do not fabricate.

`deployment-plan.json` must pass the [deployment-plan.json contract](/en/specs/deployment-plan). Persist `analysis.json` after [artifact schemas](/en/specs/artifact-schemas) validation.

## Stop conditions

| Result | Condition |
| --- | --- |
| **STOP** | Subagent cannot produce `deployment-plan.json` covering all deployable components |
| **STOP** | `deployment-plan.json` fails schema, or `analysis.json` cannot be written or pass schema |
| **CONTINUE → Phase 4** | Plan and `analysis.json` are persisted |

On Phase 3 build-definition failure, return to Phase 2 step 3 to revise `deployment-plan.json`.

## Acceptance

- `items` in `deployment-plan.json` covers all deployable components
- `analysis.json` includes `deployment_plan` with correct path
- `analysis.json` passes schema
